# 시연 대본 (2026-11-03, `v0.1.0-beta.4`)

5~7분. 프로젝터에는 **마스터 노트북의 대시보드**를 띄운다.

> beta.4로 리허설한 뒤 확정한다. 리허설에서 확인하지 못한 기능은 발표에서 "된다"고 말하지 않는다.

## 준비

**네트워크**

- 모든 기기를 **휴대폰 핫스팟이나 가져간 공유기 하나**에 붙인다. 학교·행사장 와이파이는 기기끼리 통신을 막는 경우가 많다.
- 윈도우는 그 네트워크를 **개인(Private)**으로 바꾼다(설정 → 네트워크 및 인터넷 → 속성). 방화벽 창이 뜨면 허용한다. 윈도우 앱 화면에도 같은 안내가 나온다.
- 통신은 아직 암호화되지 않는다. 믿을 수 있는 네트워크만 쓴다.

**시작 30분 전 체크리스트**

- [ ] 모든 기기에 beta.4 설치
- [ ] 충전기 연결, 자동 잠금·절전·알림 끄기
- [ ] 마스터 노트북 → 프로젝터 연결, 1280×720에서 대시보드가 잘리지 않는다
- [ ] 모든 기기가 같은 핫스팟/공유기에 붙어 있다
- [ ] 마스터 주소 확인(대시보드 **Add a machine** 카드). 핫스팟을 다시 켜면 바뀔 수 있다
- [ ] 라즈베리파이 SSH 창에 `nodeloom-agent --master <마스터 주소> --enable-fake-runner`를 입력해 두고 **Enter만 남긴다**
- [ ] 승인 상태 정리: 윈도우는 처음 승인하는 모습을 보여 줄지, 맥은 승인된 채로 "다시 켜면 자동으로 붙는다"를 보여 줄지 정한다
  - 처음 승인을 다시 보이려면 리허설 때 **Remove → 그 기기의 Pair as a new machine → 다시 승인**을 미리 해 본다. 발표 직전에 즉흥으로 Remove하지 않는다
- [ ] (AI 질문을 보여 줄 때만) 질문을 받을 기기에 Ollama와 **같은 모델**이 있고, 설치 후 Nodeloom을 다시 켰다. 대시보드 **Ask the local AI**에 모델이 보인다
- [ ] 백업 영상이 마스터 노트북에서 인터넷 없이 재생된다
- [ ] 화면에 관리 토큰·개인 알림이 보이지 않는다

## 진행

### 1. 문제 (30초)

**발표자**
> "집이나 연구실에는 맥, 윈도우 노트북, 라즈베리파이가 다 따로 놀고 있습니다. Nodeloom은 이걸 설치 한 번으로 하나의 클러스터로 묶어서, 큰 작업을 나눠 처리하게 합니다."

### 2. 클러스터 시작 (1분)

**조작 · 마스터 노트북**: Nodeloom 실행 → **Start a cluster here** → **Continue**
→ 창이 대시보드로 바뀌고 기기 1대(자기 자신)가 보인다.

**발표자**
> "이 노트북이 클러스터를 운영합니다. 터미널도, 설정 파일도 없습니다. 이 기기도 작업에 같이 참여합니다."

### 3. 기기 추가 (2분)

**윈도우 노트북**

**조작 · 윈도우**: Nodeloom 실행 → **Join a cluster** → **Continue** → 6자리 코드가 크게 뜬다.
**조작 · 마스터**: 대시보드 **Waiting for approval**의 코드와 대조 → **Approve**

**발표자** (윈도우 화면을 들어 보여 주며)
> "같은 네트워크의 클러스터를 스스로 찾았습니다. 아무 기기나 붙으면 안 되니까, 양쪽 코드를 대조해서 승인합니다."

**맥**

**조작 · 맥**: 앱 실행. 이미 승인했다면 승인 없이 바로 붙는다.

**발표자**
> "한 번 승인한 기기는 다시 켜면 알아서 붙습니다."

**라즈베리파이**

**발표자** (Add a machine 카드를 펼쳐 보여 주며)
> "화면이 없는 기기는 명령 한 줄입니다. 대시보드에 그 명령이 나와 있습니다."

**조작 · SSH**: 미리 입력해 둔 명령에서 **Enter만** 누른다.
**조작 · 마스터**: 코드 대조 → **Approve**
→ 기기 4대와 각자의 CPU·메모리가 실시간으로 보인다.

### 4. 작업 나누기 (1분)

**조작 · 마스터**: **Demo job**
→ 작업 카드에 기기별 구간 막대가 생기고 각자 채워진다.

**발표자**
> "이건 실제 렌더링이 아니라 분배를 보여 주는 테스트 작업입니다. 600개 단위가 여러 조각으로 나뉘어 기기마다 동시에 처리되고, 누가 어느 구간을 얼마나 했는지 보입니다."

4대면 약 8초에 끝난다. 끝나도 괜찮다. 다음 단계에서 새로 시작한다.

### 5. 한 대 빼기 (1분)

**발표자**
> "그럼 작업 중에 기기 하나가 갑자기 사라지면 어떻게 될까요?"

**조작 · 마스터**: **Demo job**을 새로 시작
**조작 · 맥**: 맥의 막대가 채워지는 중일 때 **바로 와이파이 끄기**
→ 맥이 목록에서 빠지고, 맥의 남은 조각이 다른 기기로 넘어가며 "Moved to another machine: 맥 → ○○"가 보인다. 작업이 **Done**으로 끝난다.

**발표자** (Done을 확인한 뒤)
> "연결이 끊긴 기기의 남은 몫을 다른 기기가 이어받아 작업을 끝냈습니다."

- 넘어간 조각은 처음부터 다시 처리된다. "이어서 했다"고 말하지 않는다.
- "10초 안에"처럼 숫자를 말하려면 리허설에서 잰 값이 그 안에 들어와야 한다.
- 여유가 있으면 맥 와이파이를 다시 켠다. 자동으로 다시 붙는다.

### 보너스: 로컬 AI에 질문 나누기 (1분, 리허설에서 성공했을 때만)

**조작 · 마스터**: **Ask the local AI** → 모델 선택 → 예시 질문 그대로 → **Ask the AI**
→ 질문이 기기들에 나뉘고, 답이 도착하는 대로 질문·답·답한 기기가 작업 카드에 보인다.

**발표자**
> "이번엔 실제 작업입니다. 각 기기에 깔린 로컬 AI에 질문 여러 개를 나눠서 묻습니다. 질문은 인터넷으로 나가지 않고, 각 기기가 자기 AI로 답합니다."

- 모델이 있는 기기에만 나뉜다. 라즈베리파이는 느릴 수 있으니 리허설에서 걸리는 시간을 본다.
- 리허설에서 한 번도 성공하지 못했다면 건너뛰고, 6단계에서 "다음 단계"로 말만 한다.

### 6. 정리 (30초)

**발표자**
> "서로 다른 기기를 묶고, 작업을 나누고, 한 대가 빠져도 끝까지 처리하는 것을 보여 드렸습니다. 다음 단계는 실제 파일 전송과 Whisper 음성 전사입니다."

(보너스를 건너뛰었다면 "각 기기의 로컬 AI에 질문을 나눠 묻는 기능"도 다음 단계로 함께 말한다.)

실제로 보여 준 것에 맞춰 말한다. 영상으로 넘어갔다면 리허설 녹화라고 밝힌다. 질문은 아래 "시연 후 피드백"에 적는다.

## 막혔을 때

| 상황 | 할 일 | 멘트 |
|---|---|---|
| Join 후 10초가 지나도 대기 목록에 안 뜬다 | 그 기기에서 **Enter the address** → Add a machine 카드의 주소 입력 → **Join this address** | "주소를 직접 넣겠습니다." |
| 윈도우만 안 붙는다 | 네트워크 "개인"·방화벽 확인 → 주소 직접 입력 → 그래도 안 되면 윈도우 없이 진행 | "윈도우는 지금 연결되지 않아, 나머지 기기로 보여 드리겠습니다." |
| 라즈베리파이가 안 붙는다 | 주소 직접 입력 → 안 되면 없이 진행 | "라즈베리파이는 지금 연결되지 않아, 나머지 기기로 보여 드리겠습니다." |
| 앱이 멈추거나 안 열린다 | 트레이 **Quit Nodeloom** 후 리허설 때 준비한 명령줄 버전으로 실행. 현장에서 새로 설치하지 않는다 | "명령줄 방식으로 바꾸겠습니다." |
| AI 질문에서 모델이 안 보이거나 답이 안 온다 | 보너스를 건너뛴다. 현장에서 Ollama를 설치하지 않는다 | "이 부분은 다음 단계로 소개만 드리겠습니다." |
| Demo job 버튼이 없다 | **Custom job** 펼치기 → Runner **Test (sleep only)** → **Split across machines** | "작업 화면에서 직접 보내겠습니다." |
| 와이파이를 껐는데 20초가 지나도 안 넘어간다 | 백업 영상으로 넘어간다. 앱을 Quit해서 넘어간 것처럼 보이게 하지 않는다 | "재배정이 늦어지고 있어, 리허설 영상으로 보여 드리겠습니다." |
| 전부 안 된다 | 백업 영상 | "현장 문제로, 리허설에서 녹화한 영상을 보여 드리겠습니다." |

백업 영상에는 연결·승인, 작업 분배, 와이파이 끄기, 재배정, 완료가 모두 담겨야 한다. 원인을 모르면 "네트워크 문제"라고 단정하지 않는다.
