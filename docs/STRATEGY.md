# 제품 전략

이 문서는 "누구를 위해, 무엇을, 왜 우리가" 만드는지를 정한다. 기능 아이디어가 이 문서와 맞지 않으면 만들지 않거나, 먼저 이 문서를 PR로 고친다.
결정의 이력은 `docs/DECISIONS.md`(D11), 근거 조사는 `docs/research/pivot-options.md`에 있다.

마지막 갱신: 2026-10-12

## 한 줄 정의

**여러 대의 맥·윈도우·리눅스 기기로 로컬 LLM을 돌리는 사람을 위해, 어떤 엔진을 쓰든 "지금 무엇이 어디서 돌고, 왜 느리고, 어디가 고장 났는지"를 한 화면에서 보여주는 관측·진단 도구.**

## 목표

1. **실사용자**: 팀 밖의 사람이 실제로 설치해서 쓴다.
2. **포트폴리오**: 팀원 각자가 맡은 부분을 설명하고 측정치로 보여줄 수 있다.

수익화는 지금 목표가 아니다. 오픈코어 계획(D6)은 보류한다.

## 타겟 사용자

| 페르소나 | 상황 | 우리가 줄이려는 고통 (가설) |
|---|---|---|
| **P1. 홈랩 개인** | 맥(Apple Silicon)과 게이밍 PC 등 2대 이상으로 한 대에 안 들어가는 큰 모델을 나눠 돌린다 | 어느 노드가 죽었는지, 왜 느린지, 링크가 RDMA인지 TCP인지 모른다 |
| **P2. 소규모 팀·동아리** | 내부용 로컬 LLM 서버 몇 대를 여러 사람이 같이 쓴다 | 어떤 모델이 어느 기기에 올라가 있고 누가 얼마나 쓰는지 모른다 |
| **P0. 우리 팀 자신** | 팀원 5명의 맥·PC로 직접 클러스터를 구성한다 | 첫 사용자이자 첫 시험대다(dogfooding) |

**아직 확인하지 못한 것**: 조사에서 확인된 불만은 대부분 설치 마찰, 크래시, 노드 2대를 넘으면 생기는 불안정 같은 **엔진 내부 문제**였다. "모니터링이 없어서 힘들다"는 불만은 직접 확인하지 못했다(조사 노트 2절). 그래서 아래 차별점은 모두 **검증할 가설**이다.

- **원문**: GitHub 등 페이지를 직접 읽음
- **요약**: 검색 결과 요약만 확인함

**결론**: 자동 발견, 모델 배치, 대시보드는 큰 엔진들이 이미 갖췄거나 갖추는 중이다. 이번 조사에서 찾지 못한 것은 **"맥(Metal)과 윈도우·리눅스 GPU를 엔진에 상관없이 관측하는 데스크톱 앱"** 이다. 다만 엔진이 대시보드를 하나씩 내장할수록 이 틈은 좁아진다.

## 차별점 (검증할 가설)

1. **엔진 무관**: Ollama, llama.cpp(server·RPC), exo를 한 화면에서 본다. 한 엔진에 묶이지 않는다.
2. **이기종 OS**: 같은 에이전트가 맥·윈도우·리눅스에서 돈다. GPUStack(리눅스 워커만)과 exo(맥 중심)가 비워 둔 "맥 + 윈도우 게이밍 PC" 조합을 노린다.
3. **진단**: "보여주기"에서 끝나지 않고 원인을 짚는다.
   - 기기 간 실제 링크 속도·지연
   - RDMA인지 TCP인지 실제 경로
   - "모델이 메모리에 안 맞음", "CPU로 떨어짐", "노드가 응답 없음" 같은 힌트
4. **안전한 기본값**:
   - 에이전트는 페어링 토큰이 있어야 붙고, 임의 명령을 실행하지 못한다(절대 규칙 1·4번).
   - 열린 네트워크에서 위험한 엔진(llama.cpp RPC 서버)이 외부에 노출돼 있으면 경고한다.

## 하지 않을 것

- **추론 엔진을 직접 만들지 않는다.** 엔진은 exo, llama.cpp, Ollama 같은 기존 프로젝트의 몫이다.
- **추론 속도를 올려 준다고 주장하지 않는다.** 기기 간 링크(Thunderbolt 약 5GB/s)가 메모리 대역폭(수십~수백 GB/s)보다 훨씬 느린 물리 한계는 관측 도구로 해결되지 않는다. 우리의 가치는 **세팅 시간 단축과 고장 진단**이다.
- **임의 코드를 실행하지 않는다.** 실행 기능은 아래 P2에서 따로 결정한다.
- **실시간 뷰포트·게임 가속, Blender 분산 렌더 신규 기능**: 보류한다(D10, D11).

## 로드맵

각 단계는 "끝났다"의 기준을 만족해야 다음 단계로 간다. 기간은 팀 상황에 따라 정하고, 여기에는 순서만 적는다.

### P0. 관측: "무엇이 어디서 돌고 있나"

- **GPU 지표**: NVIDIA부터 시작하고, Apple Silicon은 권한 문제를 스파이크로 먼저 확인한다. 사용률, 메모리, 온도, 전력을 모은다.
- **엔진 어댑터**: Ollama(`/api/ps`), llama.cpp server(`/metrics`)부터 시작하고 exo API를 뒤에 붙인다. 로드된 모델, 메모리 사용, 처리 중 요청을 읽는다.
- **화면**: 기기별 GPU 카드와 "어떤 모델이 어느 기기에 올라가 있나" 표.
- **끝났다의 기준**: 팀 dogfooding 클러스터(기기 2대 이상, 엔진 2종 이상)를 일주일 동안 이 화면만 보고 운영할 수 있다.

### P1. 진단: "왜 느리고 어디가 고장 났나"

- 에이전트 사이 링크 속도·지연 측정. 측정은 고정된 내장 기능으로만 하고, 임의 명령을 받지 않는다.
- RDMA/TCP 경로 표시와 원인 힌트(메모리 부족, CPU 폴백, 노드 무응답).
- 알림: 노드 이탈, 메모리 부족, 과열.
- 이력: 지난 24시간 그래프.
- **끝났다의 기준**: 팀이 겪은 실제 장애나 느림 사례 3건 이상을 이 도구로 원인까지 찾았다는 기록이 있다.

### P2. 보조: "세팅을 줄여 준다" — 시작 전 팀 결정 필요

- 기기별 모델 파일(GGUF·MLX) 목록과 복사, 해시 검증.
- 화이트리스트 엔진을 고정 설정으로 실행. 예: `rpc-server`를 정해진 포트로 띄우기.
  - 고정된 프로그램과 검증된 인자만 쓰므로 규칙 1번(닫힌 enum) 안에 들어간다.
  - 그래도 실행 기능이므로 **이슈에서 합의하고 A가 승인한 뒤 `docs/DECISIONS.md`에 기록하고 시작한다.**

### P3. 공유: "팀이 같이 본다"

- 팀원 읽기 전용 접근, 사용자·모델별 사용량.
- 원격 접근이 필요해지면 그 전에 TLS를 적용한다(#6).

## 성공 지표

아래 숫자는 근거 있는 기준이 아니라 **팀이 확정할 제안값**이다.

| 지표 | 제안 목표 |
|---|---|
| 팀 dogfooding 클러스터 연속 운영 | 2주 |
| 이 도구로 원인을 찾은 실제 사례 기록 | 3건 |
| 팀 밖 설치 사용자 | 5명 |
| 대화(인터뷰)한 타겟 사용자 | 5명 이상 |
| 공개 데모 글 또는 영상 | 1건 |

## 검증 순서

1. **dogfooding**: 팀원 기기로 exo, llama.cpp RPC, Ollama를 직접 세팅한다. 단계 수, 걸린 시간, 막힌 순간, "상태를 몰라서 답답했던 순간"을 기록한다. 이 기록이 P0·P1 우선순위의 근거가 된다.
2. **인터뷰**: `docs/research/interview-guide.md`의 로컬 AI 질문으로 5명 이상과 대화한다.
3. **공개 데모**: P0 화면으로 데모를 만들어 커뮤니티에 올리고 반응과 대기자 등록을 본다.

dogfooding 기록에 "상태를 몰라 답답했던 순간"이 거의 없거나, 인터뷰에서 모니터링이 상위 고통으로 나오지 않으면 이 방향을 다시 검토한다.

## 기술 위험 (먼저 확인할 것)

| 위험 | 확인 방법 |
|---|---|
| 맥 GPU 지표를 관리자 권한 없이 읽을 수 있는가. `powermetrics`는 관리자 권한이 필요한 것으로 알고 있으나 확인하지 않음 | 스파이크 이슈 |
| NVIDIA 지표를 NVML Rust 바인딩으로 읽을지, `nvidia-smi`를 인자 목록으로 실행해 읽을지 | 스파이크 이슈 |
| 엔진 API(Ollama, llama-server, exo)가 자주 바뀌어 어댑터가 깨질 위험 | 어댑터마다 버전을 기록하고, 실패해도 다른 화면은 동작하게 |
| 엔진들이 자체 대시보드를 강화해 우리 가치가 줄어들 위험 | 엔진 무관·이기종 OS·진단에 집중. 단일 엔진 대시보드와 겹치는 기능은 만들지 않음 |

## 기존 코드에서 쓰는 것

- **그대로 재사용**: 에이전트·마스터 연결, mDNS 자동 발견, 페어링 토큰(`tokens_match`), 노드 이탈 처리, WebSocket 스냅샷, UI 컴포넌트(`NodeCard`, `Meter`, `Sparkline`, `StatusBadge`).
- **보류**: Blender 러너와 프레임 분할. 러너 구조의 예시로 코드는 남긴다.
- **새로 만듦**: GPU 지표 수집, 엔진 어댑터, 모델 화면, 링크 진단.
