# Nodeloom 시연 대본 (포스터 연계)

Nov 3, 2026 · @깡통

## 한눈에 보기

시연은 **포스터로 "무엇·왜"를 말하고, 화면으로 "진짜 된다"를 보여 주는** 구조다. 풀 대본은 약 7분이고, 포스터 위에서 아래 순서대로 내려가며 화면과 번갈아 짚는다. 기준은 docs/DEMO.md(E 담당)이고, 포스터 구역과 "1대 vs 여러 대" 비교, 로컬 AI 작업을 더했다.

| 단계 | 시간 | 어디를 보나 | 핵심 한 줄 |
|---|---|---|---|
| 1. 인사와 문제 | 0:30 | 포스터 제목 · 프로젝트 소개 | 따로 노는 컴퓨터를 설치만으로 묶는다 |
| 2. 혼자서 하면 | 0:40 | 화면(기기 1대) | 마스터 한 대로 Demo job → 약 30초 걸린다 |
| 3. 기기 붙이기 | 1:30 | 포스터 작동 흐름도 01·02 → 화면 | 코드 한 번 대조로 승인, 화면 없는 기기는 명령 한 줄 |
| 4. 나눠서 하면 | 1:00 | 화면(연결된 기기 전부) → 흐름도 03·04 | 같은 작업이 기기 수만큼 빨라지고(2대면 약 15초), 색 구간이 동시에 찬다 |
| 5. 한 대 빼기 | 1:00 | 화면 | 와이파이를 끄면 그 몫이 다른 기기로 넘어가 끝난다 |
| 6. 진짜 작업(선택) | 1:00 | 화면 | 기기마다 로컬 AI가 질문을 나눠 답한다 |
| 7. 어떻게 만들었나 | 1:00 | 포스터 구조 · 테스트 · 비교 | 닫힌 작업 타입, 기기 서명 키, 자동 테스트 |
| 8. 마무리 | 0:30 | 포스터 일정·향후 계획 | 다음은 파일 전송과 Whisper |

**자리 배치**

- 포스터는 화면(노트북 A 또는 모니터) **왼쪽**에 세운다. 사람은 왼쪽에서 오른쪽으로 읽으니 "포스터로 설명 → 화면으로 확인" 순서가 자연스럽다.
- 발표자는 포스터와 화면 사이에 서서 두 곳을 손으로 짚는다. 조작자는 화면 옆에 앉고, 와이파이를 끌 Mac을 손이 닿는 곳에 둔다.
- 라즈베리파이는 이번에 가져가지 않는다. 3단계에서 "명령 한 줄로 붙는다"고 말로만 설명한다.
- 시간이 짧거나 사람이 몰리면 아래 **짧은 대본**으로 바꾼다. 교대·예상 질문은 앞서 만든 [시연 시나리오 초안](https://claude.ai/artifact/6VUr9AMX6JVMWW9PcCTmZk)을 함께 본다.

## 포스터 구역별로 짚을 내용

포스터는 10월 24일 기준이라, 그 뒤 만든 기능(Demo job·구간 막대·재배정 표시·로컬 AI·문서 요약·설치 파일)은 **화면으로 보여 주고 말로 덧붙인다.** 구역마다 한두 문장만 짚고 넘어간다.

| 포스터 구역(위→아래) | 짚을 때 하는 말 | 대본 단계 |
|---|---|---|
| 제목·한 줄 소개 | "팀원들의 제각각 컴퓨터를 설치만으로 묶어, 오래 걸리는 작업을 나눠 처리하는 도구입니다." | 1 |
| 팀원·역할 표 | 역할별로 영역을 나눠 동시에 개발했다는 근거. 질문이 오면 "이 부분은 담당인 ○○가 답하겠습니다"로 연결한다 | 7, 질문 |
| 프로젝트 소개 | 맥·윈도우·리눅스·라즈베리파이를 한 번 승인으로 묶는다. 포스터의 "강의 녹음"(Whisper)은 아직 개발 중이라 말로 약속하지 않는다 | 1 |
| 주요 기능 4개 | 시연의 목차로 쓴다. "이 네 가지를 차례로 화면으로 보여드리겠습니다." | 1 |
| 기대 효과 | "긴 작업 시간을 줄인다"는 말은 2·4단계의 30초 → 약 8초 비교로 보여 준다. 단, 테스트 작업이라 원리를 보여 주는 것이라고 밝힌다 | 4 |
| 시스템 작동 흐름도 01~04 | 01·02는 기기 붙이기 직전에, 03·04는 작업 나누기와 한 대 빼기 직전에 짚고 바로 화면으로 돌아간다 | 3, 4, 5 |
| 시스템 구조 | 대시보드 → 마스터(허브) → 에이전트 3종. "각 기기는 서명 키로 접속하고, 명령 문자열은 실행하지 않고 검증된 내장 작업만 합니다." | 7 |
| 실제 대시보드 화면 | 포스터 사진은 예전 화면이다. 짚지 말고 "지금 화면은 여기서 더 발전했습니다"라며 실제 화면을 가리킨다 | --- |
| 구성 요소별 자동 테스트 | 포스터는 118개(10월 기준). 지금은 Rust 약 140개, UI 약 100개로 늘었고 5개 플랫폼 CI에서 매번 돈다 | 7 |
| 기존 도구와의 비교 | Beszel은 관측만, Slurm은 전문가용, exo는 특정 작업 전용. Nodeloom은 섞인 개인 기기 + 설치와 승인 1번 | 7 |
| 개발 일정·향후 계획 | 1~3단계 완료. 4단계는 진행 중이며, 포스터 이후 설치 파일·로컬 AI 작업·문서 요약을 더 만들었다. 남은 것은 작업 파일 전송, Whisper, 통신 암호화(TLS) | 8 |

## 풀 대본 (약 7분)

시작 상태: 노트북 A(마스터) 앱과 대시보드만 켜져 있고, **기기는 A 한 대뿐**이다. 노트북 B·Mac 앱은 꺼 둔다. 기록 담당이 있으면 휴대폰 스톱워치를 준비한다. 화면에 걸린 시간이 표시되지 않기 때문이다.

### 1. 인사와 문제 · 0:30 · 포스터 상단

- **발표자**(제목을 가리키며): "안녕하세요, 팀 노드메이트의 Nodeloom입니다. 팀이나 연구실에는 맥, 윈도우 노트북, 라즈베리파이가 제각각 따로 놉니다. Nodeloom은 이걸 설치만으로 하나로 묶어서, 오래 걸리는 작업을 나눠 처리합니다."
- (주요 기능 4개를 훑으며) "여기 네 가지를 지금 화면으로 직접 보여드리겠습니다."
- 한계도 먼저 말해 둔다: "모든 작업이 빨라지는 건 아니고, 파일 묶음처럼 나눌 수 있는 작업이 대상입니다."

### 2. 혼자서 하면 · 0:40 · 화면

- **발표자**: "지금은 이 노트북 한 대만 있습니다. 테스트 작업을 하나 돌려 보겠습니다."
- **조작자**: **Demo job**. 버튼 옆 안내에 "split across 1 machine, about 30 s"가 보인다. 기록 담당은 스톱워치를 누른다.
- **발표자**: "600개 단위를 한 대가 혼자 처리하니 약 30초 걸립니다. 기다리는 동안 기기를 붙여 보겠습니다."
- 이 작업은 누른 순간의 기기 수로 나뉘므로, 나중에 붙는 기기는 이 작업을 받지 않는다. 그래서 일부러 기기를 붙이기 전에 누른다.

### 3. 기기 붙이기 · 1:30 · 포스터 흐름도 01·02 → 화면

- **발표자**(흐름도 01·02를 짚으며): "기기마다 설치하고, 확인 코드를 보고 한 번만 승인하면 됩니다."
- **노트북 B(윈도우)**: 앱 실행 → **Join a cluster** → 6자리 코드. 대시보드에 **Waiting for approval**이 뜨면 코드를 대조해 **Approve**.
  - 발표자: "같은 네트워크의 클러스터를 스스로 찾았습니다. 아무 기기나 붙으면 안 되니까 코드를 대조해서 승인합니다."(노트북 B 화면을 들어 보여 준다)
- **Mac**: 이미 승인된 상태에서 앱만 켠다. "한 번 승인한 기기는 다시 켜면 알아서 붙습니다."
- **라즈베리파이**: 실물 없이 설명만 한다. 대시보드의 기기 추가 카드를 펼쳐 명령줄을 가리키며: "라즈베리파이처럼 화면이 없는 기기는 이 명령 한 줄로 붙고, 똑같이 코드를 대조해 승인합니다. 오늘은 노트북으로만 보여드리지만 방식은 같습니다."
- 화면: 연결된 기기들이 각자 CPU·메모리와 함께 보인다. 새 화면이라면 연결도에서 마스터와 이어지는 선이 하나씩 생긴다.
- 그사이 2단계 작업이 **Done**이 된다. 기록 담당이 걸린 시간을 알려 준다(예: "30초").

### 4. 나눠서 하면 · 1:00 · 화면 → 흐름도 03·04

- **발표자**: "이제 똑같은 작업을 연결된 기기 모두로 해 보겠습니다."
- **조작자**: **Demo job**. 안내 문구의 기기 수와 예상 시간이 바뀐 것을 한 번 짚는다(2대면 약 15초, 3대면 약 10초). 스톱워치 시작.
- 화면: 작업 막대가 기기 수만큼의 색 구간으로 나뉘어 동시에 찬다. 기기마다 "Job · frames ..."가 뜬다.
- **발표자**: "색이 기기입니다. 600개를 기기 수대로 나눠 동시에 처리합니다. 화면에 나오듯이 혼자 하면 약 30초, 두 대가 나누면 약 15초입니다."
- 정직하게 덧붙인다: "지금 작업은 기다리기만 하는 테스트라서, 나눠 처리하는 원리를 보여 드린 겁니다. 실제 성능 수치는 아닙니다."
- (흐름도 03·04를 짚으며) "작업을 올리면 나눠 처리하고, 기기가 빠지면 다시 배정합니다. 마지막 것을 보여드리겠습니다."

### 5. 한 대 빼기 · 1:00 · 화면

- **발표자**: "기기 하나가 갑자기 사라지면 어떻게 될까요?"
- **조작자**: 새 **Demo job**을 누르고 **곧바로** Mac 와이파이를 끈다. 다른 구간은 금방(2대면 약 15초) 끝나니 늦게 끄면 보여 줄 게 없다.
- 화면 순서: Mac 구간만 멈춘다 → 약 10초 뒤 Mac이 목록에서 빠지고 **"Moved to another machine ... Mac → ..."** 배너 → 그 구간이 다른 기기 색으로 처음부터 다시 찬다 → **Done**. 새 화면이라면 연결도에서 Mac이 점선·회색(offline)으로 바뀐다.
- **발표자**(멈춘 동안): "마스터는 기기가 10초 동안 아무 신호도 없으면 끊긴 것으로 봅니다."
- **발표자**(Done 뒤): "끊긴 기기의 몫을 다른 기기가 받아 작업을 끝냈습니다. 넘겨받은 조각은 처음부터 다시 처리합니다." 배너는 Done 뒤에도 잠시 남고, 목록의 "→ moved from Mac"은 계속 보인다.
- **이 장면이 끝날 때까지 새 작업을 넣지 않는다.** 새 작업이 들어오면 이 작업 카드가 아래로 밀리거나 접힌다.

### 6. 진짜 작업: 로컬 AI에 질문 나누기 · 1:00 · 화면 (리허설에서 됐을 때만)

- **발표자**: "방금까지는 테스트였고, 이번엔 실제 작업입니다. 각 기기에 설치된 로컬 AI가 질문을 나눠 답합니다."
- **조작자**: Start a job의 **Ask the local AI**에서 모델을 고르고 예시 질문 그대로 **Ask the AI**.
- 화면: 질문이 기기별로 나뉘고, **Answers**에 질문·답·답한 기기가 쌓인다.
- **발표자**: "답 옆에 어느 기기가 답했는지 나옵니다. 질문은 외부 클라우드로 나가지 않고, 각 기기는 자기 컴퓨터에 설치된 AI에만 묻습니다."
- 모델이 있는 기기에만 간다. 리허설에서 안 됐거나 시간이 부족하면 이 단계는 빼고 "다음 단계로 준비 중"이라고만 말한다.

### 7. 어떻게 만들었나 · 1:00 · 포스터 구조·테스트·비교

- (시스템 구조를 짚으며) "구성은 대시보드, 허브 역할의 마스터, 기기마다 도는 에이전트입니다. 각 기기는 자기 서명 키로 접속하고, 네트워크로 받은 명령은 실행하지 않으며 검증된 내장 작업만 합니다."
- (팀원·역할 표) "다섯 명이 코어, 에이전트, UI, 배포, QA로 나눠서, 이슈 → 브랜치 → PR → 자동 테스트·리뷰를 거쳐 합쳤습니다."
- (자동 테스트) "포스터를 만들 때 118개였던 자동 테스트가 지금은 Rust 약 140개, UI 약 100개이고, 리눅스·맥·윈도우 5개 환경에서 매번 돈다."
- (기존 도구 비교) "비슷한 도구는 관측만 하거나, 전문가용이거나, 특정 작업 전용입니다. 저희는 섞인 개인 기기를 설치와 승인 한 번으로 씁니다."

### 8. 마무리 · 0:30 · 포스터 개발 일정·향후 계획

- **발표자**: "오늘은 서로 다른 기기의 연결과 승인, 작업 분배, 기기가 빠졌을 때의 재배정을 보여드렸습니다. 다음은 작업 파일 전송과 강의 녹음 전사(Whisper), 통신 암호화입니다. 질문 받겠습니다."
- 실제로 성공한 단계만 말한다. 영상으로 바꿨다면 "리허설에서 녹화한 화면"이라고 밝힌다.
- 끝난 뒤 Mac 와이파이를 다시 켜서 자동으로 다시 붙는지 확인한다.

## 짧은 대본 (2~3분)

발표회 중간에 지나가는 관람객용이다. 시연 기기들이 이미 붙어 있는 상태에서 시작하고, 포스터는 제목과 흐름도만 짚는다.

1. **한 줄 소개 (20초)** · 포스터 제목: "팀원들의 제각각 컴퓨터를 설치만으로 묶어, 오래 걸리는 작업을 나눠 처리하는 도구입니다. 지금 이 기기들이 하나로 묶여 있습니다."(화면의 기기 목록과 실제 기기를 가리킨다)
2. **나눠서 처리 (40초)** · 화면: Demo job → "색이 기기입니다. 화면에 나오듯이 혼자 하면 약 30초, 두 대가 나누면 약 15초입니다. 단, 원리를 보여 드리는 테스트 작업입니다."
3. **한 대 빼기 (1분)** · 화면: 새 Demo job + 곧바로 Mac 와이파이 끄기 → "10초 동안 신호가 없으면 끊긴 걸로 보고..." → 배너 → Done → "빠진 기기의 몫을 다른 기기가 끝냈습니다."
4. **질문 받기** · 설계·보안 질문이면 포스터 시스템 구조로, 개발 과정 질문이면 자동 테스트·팀원 표로 넘어간다.

끝나면 Mac 와이파이를 다시 켜서 다시 모두 붙은 것을 확인하고 다음 관람객을 받는다. 다음 시연에서는 새 작업 카드만 보면 된다.

## 주의할 점과 시연 전 확인

### 포스터와 실제가 다른 곳

포스터는 10월 24일 기준이다. 아래는 **포스터를 그대로 읽으면 틀리거나 과장이 되는** 부분이다.

- **강의 녹음(Whisper)**: 아직 구현 전이다. "지금 됩니다"가 아니라 "다음 단계"로만 말한다.
- **"파일 묶음 자동 분할·분배"**: 오늘 보여 주는 것은 테스트 단위(프레임)와 질문 목록을 나누는 것이다. 파일을 기기로 보내는 기능(작업 파일 전송)은 향후 계획이다. 문서 요약은 대시보드에서 글만 뽑아 나누는 방식이다.
- **기대 효과의 "시간 단축"**: 실측 수치가 없다. 30초 → 약 8초는 기다리기만 하는 테스트의 계산값이라고 한 번은 밝힌다. 포스터에도 "실측 후 추가"라고 적혀 있다.
- **실제 대시보드 화면 사진**: 예전 화면(250프레임 Job 2)이다. 실제 화면을 보여 주며 "더 발전했다"고 말한다.
- **자동 테스트 118개**: 지금은 더 많다(Rust 약 140, UI 약 100). 정확한 수를 말하려면 시연 전에 CI 결과로 확인한다.
- **향후 계획의 "설치 파일·자동 실행"**: 이미 만들었다(beta 설치 파일). "포스터 이후 완료"라고 말해도 된다.
