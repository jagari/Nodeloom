## P0-1. 시연 대본 `docs/DEMO.md`

5~7분 분량으로, 누가 어느 기기에서 무엇을 누르는지 단계별로 쓴다. 뼈대는 다음과 같다. 순서와 문구는 팀과 정한다.

1. **문제**(30초): 각자 가진 맥, 윈도우, 라즈베리파이가 따로 논다.
2. **클러스터 시작**(1분): 노트북 A에서 앱 → Start a cluster here → 대시보드
3. **기기 추가**(2분)
   - 윈도우 노트북: Join a cluster → 코드 대조 → Approve
   - 맥: 같은 방법. 미리 승인해 두고 "다시 켜면 자동으로 붙는다"를 보여 줘도 된다.
   - 라즈베리파이: 명령줄 한 줄. 대시보드의 Add a machine 카드에서 복사한다.
4. **작업 나누기**(1분): Demo job 버튼 → 기기별 구간 막대(C)
5. **한 대 빼기**(1분): 한 대의 와이파이를 끈다 → 그 몫이 넘어가 끝난다(A·B)
6. **정리**(30초): 다음 단계는 Whisper 배치 전사다(#26).

꼭 들어가야 하는 것:

- **장비와 네트워크**
  - 휴대폰 핫스팟이나 가져간 공유기 하나에 모든 기기를 붙인다. 행사장·학교 와이파이는 기기끼리 통신을 막는 경우가 많다.
  - 윈도우는 그 네트워크를 "개인"으로 설정해 둔다.
- **사전 준비 체크리스트**: 설치 버전(beta.4), 충전, 화면 미러링, 자동 잠금 끄기, 알림 끄기
- **실패했을 때의 대안**
  - 자동 탐색이 안 됨 → Enter the address
  - 앱이 이상함 → 명령줄 버전
  - 전부 안 됨 → 미리 녹화한 영상

## P0-3. 문서 통합 (다른 PR이 병합된 뒤)

- 각 PR 본문의 "문서 반영 요청"을 모아 반영한다.
  - `docs/STATUS.md`: 갑자기 꺼진 기기 감지, 테스트 수 등
  - `docs/ARCHITECTURE.md`: 시간 제한, 대시보드 화면
  - `docs/BETA.md`: 버전 표기, Demo job
- `CHANGELOG.md`에 `## [0.1.0-beta.4] - <날짜>` 절을 쓴다. **D가 버전을 올리기 전에 병합해야 한다.** 릴리즈 워크플로가 이 절을 릴리즈 노트로 쓰고, 없으면 실패한다.
