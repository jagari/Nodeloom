# 역할 A: 마스터·코어 (이슈 #35)

- **브랜치**: `feat/35-dead-agent`
- **고칠 수 있는 파일**: `crates/nodeloom-master/**`, `crates/nodeloom-core/**`
- **리뷰어**: B
- 규칙과 계약은 `docs/handoff/README.md`. 특히 공개 API와 HTTP 응답 모양은 바꾸지 않는다.

## 왜 중요한가

시연의 하이라이트는 "기기 하나를 끄면 그 몫이 다른 기기로 넘어간다"이다.

- 지금은 에이전트가 **정상 종료**할 때만 바로 넘어간다. 앱 종료, Ctrl+C, 대시보드의 Remove가 해당한다.
- **와이파이를 끄거나 전원을 뽑으면** 넘어가지 않는다. TCP는 끊긴 줄 모르고, 마스터의 승인된 기기 세션에는 시간 제한이 없다.
  - `crates/nodeloom-master/src/server.rs`의 `agent_session` 안 `loop { tokio::select! { … socket.recv() … } }`(약 360~394행)
  - 결국 운영체제의 TCP 시간 초과(수 분~수십 분)까지 기다린다.

## P0-1. 조용해진 기기를 10초 안에 끊고 재배정

1. `state.rs`의 `Settings`에 필드 두 개를 **추가**한다. 기존 필드와 기본값은 그대로 둔다. 테스트는 짧은 값을 쓴다.
   - `agent_idle_timeout` (기본 10초)
   - `agent_ping_interval` (기본 3초)
2. 승인된 세션 루프에서 **아무 프레임이나**(Text, Ping, Pong, Binary) 받을 때마다 마지막 수신 시각을 갱신한다.
3. `agent_ping_interval`마다 `Message::Ping`을 보낸다. 시각을 확인해 `agent_idle_timeout`을 넘었으면 `warn!` 로그를 남기고 루프를 빠져나간다.
   - 빠져나가면 기존 경로(`unregister_node`)가 작업을 재배정한다.
   - 에이전트는 Metrics를 1초마다 보내고 Ping에는 자동으로 Pong한다. 그래서 정상 기기는 끊기지 않는다.
4. **테스트**(`tests/e2e.rs`): 원시 에이전트로 시나리오를 만든다. 기존 헬퍼 `raw_hello`를 쓴다.
   1. 토큰으로 붙어서 작업을 받는다.
   2. 이후 소켓은 열어 둔 채 아무것도 보내지 않고, 읽지도 않는다.
   3. 그 작업이 다른 (진짜) 에이전트로 넘어가 끝나는지 확인한다.
   4. 스냅샷 `nodes`에서 그 기기가 사라지는지 확인한다.
   - 시간은 `Cluster::with_settings`로 줄인다(예: 300ms·100ms).
5. 기존 e2e 테스트가 모두 그대로 통과해야 한다. 짧은 시간 제한 때문에 정상 에이전트가 끊기면 안 된다.

**완료 기준**
- 위 테스트가 통과한다.
- 실기기 확인: 노트북 2대로 테스트 작업 중에 한 대의 와이파이를 끄면, 15초 안에 남은 기기에서 작업이 끝난다(E와 함께).
- 결과를 PR에 적는다.

## P0-2. 시연 규모 확인 테스트

- e2e 시나리오: 에이전트 5대, 프레임 200개짜리 작업을 시작한다. 처리 중에 2대를 끊는다. 하나는 `abort`, 하나는 위의 "조용해짐" 방식으로 끊는다. 그래도 작업이 모두 `Done`인지 확인한다.
- 실패하면 원인을 고친다. 재배정 로직은 `state.rs`에 있다.

## P1. 작업을 기기 수보다 잘게 나누기 (시간이 남으면)

- 지금은 기기 수만큼만 나눈다(`nodeloom-core/src/split.rs`, `Cluster::submit_job`). 그래서 기기가 하나 빠지면 그 몫 전체를 처음부터 다시 한다.
- 기기 수 × 2~4개로 나누고, 기기가 하나를 끝내면 다음 조각을 받게 한다.
  - 진행이 고르게 보이고, 재배정 손실도 줄어든다.
  - `TaskView` 목록 모양은 그대로라 UI(C)는 바꿀 필요가 없다. 한 기기가 여러 조각을 차례로 맡는 것은 지금 UI도 표시한다.
- 테스트: 분할 단위 테스트, 그리고 위 e2e가 그대로 통과하는지 본다.
