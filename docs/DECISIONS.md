# 결정 기록

중요한 결정은 여기에 한 항목씩 추가한다. 이미 내린 결정을 뒤집을 때도 지우지 말고 새 항목을 추가해 이유를 남긴다.
형식: 날짜 · 결정 · 이유 · 영향.

## D1. 작업 분산만 하고 실시간 가속은 하지 않는다 (2026-10-12)

- **결정**: 렌더링·빌드처럼 독립 단위로 나눌 수 있는 작업만 분산한다. 뷰포트나 게임 실행 fps는 다루지 않는다.
- **이유**: 기기 간 연결(Thunderbolt 약 5GB/s)이 GPU 메모리 대역폭(수십~수백 GB/s)보다 훨씬 느리고, 프레임마다 왕복 지연이 생긴다.
- **영향**: 마케팅과 문서에서 "노트북이 빨라진다"는 식의 표현을 쓰지 않는다.

## D2. 제품 이름은 nodeloom (2026-10-12)

- **결정**: 처음 정한 `nodeweave` 대신 `nodeloom`을 쓴다.
- **이유**: npm에 같은 이름(`nodeweave`, 웹 시각화 라이브러리)이 이미 있었다. `nodeloom`은 crates.io·npm·PyPI 모두 비어 있었다.
- **영향**: 도메인과 상표(KIPRIS, USPTO 제9·42류)는 아직 확인하지 못했다. 유료 판매 전에 확인한다. 앱 식별자는 임시로 `io.github.jagari.nodeloom`이다.

## D3. 코어는 Rust, UI는 Tauri + Svelte (2026-10-12)

- **결정**: 에이전트·마스터는 Rust, 데스크톱 UI는 웹 기술(Svelte·TypeScript)을 Tauri로 감싼다. Flutter는 쓰지 않는다.
- **이유**: 코어가 Rust라 Tauri는 브리지 계층 없이 붙는다. 대시보드(차트·표)는 웹 생태계가 유리하다. 단일 실행 파일로 맥·윈도우·리눅스에 배포하기 쉽다.
- **영향**: 팀 대부분이 Rust 경험이 없어, Rust 영역은 담당 A의 리뷰를 필수로 한다.

## D4. UI와 코어는 로컬 API로 분리한다 (2026-10-12)

- **결정**: UI는 마스터의 HTTP/WebSocket API만 쓴다. Tauri 전용 명령(IPC)은 만들지 않는다.
- **이유**: 나중에 모바일 앱이나 웹 대시보드를 같은 API에 붙일 수 있고, UI 프레임워크 선택을 되돌릴 수 있게 된다.
- **영향**: 다른 출처의 UI가 API를 부르므로 마스터는 CORS를 허용한다(토큰 인증이라 안전).

## D5. 작업은 닫힌 enum이고 임의 명령은 실행하지 않는다 (2026-10-12)

- **결정**: 작업 종류는 `TaskPayload` enum으로 고정한다. 검증은 마스터와 에이전트 양쪽에서 하고, 외부 프로그램은 셸 없이 실행하며, Blender는 `--disable-autoexec`로 실행한다.
- **이유**: 에이전트는 네트워크로 받은 지시를 실행하는 프로그램이라, 범용 명령 실행을 허용하면 같은 네트워크의 누구나 원격 코드 실행을 할 수 있게 된다. `.blend` 파일은 내장 파이썬 스크립트를 담을 수 있다.
- **영향**: 새 작업 종류는 proto 변경과 검증 규칙 추가가 필요하다.

## D6. 수익 모델은 오픈코어 (2026-10-12)

- **결정**: 코어는 Apache-2.0 오픈소스로 공개한다. Pro 기능(기기 수 확장, 작업 우선순위, 이력·리포트, 알림, 추가 러너, 원격 접속)은 별도 비공개 저장소에 둔다. 결제는 판매대행(MoR) 서비스를 검토한다.
- **이유**: 무료 코어로 사용자를 모으고, 이미 공개한 코드의 라이선스를 바꿀 일이 생기지 않게 한다.
- **영향**: 외부 기여를 받으면 라이선스 변경이 어려워지므로, 받기 전에 CLA 또는 DCO를 정한다. 가격은 사용자 인터뷰 후에 정한다(가설: 월 $5~9 또는 평생 $49~79).

## D7. Tauri 셸은 Cargo 워크스페이스에서 뺀다 (2026-10-12)

- **결정**: `apps/desktop/src-tauri`는 별도 `Cargo.lock`과 빌드 폴더를 쓴다.
- **이유**: 리눅스에서 Tauri를 빌드하려면 WebKitGTK 등 GUI 라이브러리가 필요하다. 코어 테스트(`cargo test --workspace`)가 그 라이브러리 없이 돌아야 한다.
- **영향**: CI에 데스크톱 셸 빌드를 별도 작업으로 둔다.

## D8. UI는 TypeScript 6에 고정 (2026-10-12)

- **결정**: `typescript`를 `~6`으로 고정한다.
- **이유**: svelte-check 4.7이 TypeScript 7 단독 설치를 지원하지 않는다.
- **영향**: svelte-check가 TypeScript 7을 지원하면 다시 검토한다.

## D9. 작업 관리는 GitHub Issues, 컨텍스트는 저장소에 (2026-10-12)

- **결정**: 할 일과 담당자는 GitHub Issues로 관리한다. 팀과 LLM이 공유할 규칙·배경은 저장소 파일(`AGENTS.md`, `docs/`)에 둔다.
- **이유**: 팀원 5명이 서로 다른 LLM 도구(Claude, ChatGPT, Codex, Gemini)를 쓴다. 채팅 기록은 공유되지 않으므로 저장소가 유일한 공통 기준이어야 한다.
- **영향**: 규칙 원본은 `AGENTS.md` 하나이고, `CLAUDE.md`와 `GEMINI.md`는 그것을 가져온다. 채팅형 도구에는 `scripts/llm-context.py` 출력을 붙여 넣는다.
