# 시연 대본 (2026-11-03, `v0.1.0-beta.4`)

> 준비용 초안. 목표 빌드는 beta.4이며, 아래 기능과 기대 결과는 해당 빌드로 리허설한 뒤 확정한다. 특히 Demo job·구간 막대·이동 표시(C), 갑작스러운 통신 단절 감지·재배정(A·B)은 확인 전 성공으로 기록하지 않는다.

5~7분 시연이다. 사람은 **발표자** 한 명과 **조작자** 한 명 이상으로 나눈다. 발표자는 설명에 집중하고, 조작자는 기기를 조작한다. 인원이 부족하면 겸임할 수 있다. 화면에는 노트북 A(마스터)의 대시보드를 띄운다.

| 기기 | 역할 | 설치 | 조작자 |
|---|---|---|---|
| 노트북 A | 마스터 (Start a cluster here). 프로젝터에 연결 | 데스크톱 앱 beta.4 | (이름) |
| 노트북 B (윈도우) | 참여 (Join a cluster) | 데스크톱 앱 beta.4 | (이름) |
| 맥 | 참여 (Join a cluster) | 데스크톱 앱 beta.4 | (이름) |
| 라즈베리파이 | 참여 (명령줄). SSH로 조작 | `linux-arm64` 명령줄 beta.4 | (이름) |

노트북 A·B는 장비 구분이며 개발 역할 A·B와는 다르다. 발표자와 기기 조작자는 팀에서 확정한다.

### 팀과 확정할 항목

| 항목 | 확정 내용 |
|---|---|
| 발표 시간·장소 | 미정 |
| 발표자 / 시간·기록 담당 | 미정 / E |
| 기기별 조작 담당 | 위 기기 표에 채운다 |
| 와이파이를 끌 기기 | 참여 기기인 Mac 권장, 리허설에서 확정 |
| 공통 네트워크 / 준비 담당 | 핫스팟 또는 가져간 공유기 / 미정 |
| beta.4 배포 시각 / 리허설 2회 시각 | D에게 확인 / 미정 |
| 화면 녹화 담당 / 백업 영상 위치 | 미정 / 미정 |

## 장비와 네트워크

- **휴대폰 핫스팟이나 가져간 공유기 하나**에 모든 기기를 붙인다. 행사장·학교 와이파이는 기기끼리 통신을 막는 경우가 많아서 쓰지 않는다.
- 윈도우 노트북은 그 네트워크를 **개인(Private)**으로 바꿔 둔다. 설정 → 네트워크 및 인터넷 → 속성. 방화벽 창이 뜨면 개인 네트워크를 허용한다.
- 마스터가 윈도우라면 마스터도 같은 설정을 한다.
- 핫스팟에서도 기기 간 통신이 가능한지 리허설에서 확인한다. 통신은 아직 암호화되지 않으므로 신뢰하는 네트워크를 사용한다.
- 라즈베리파이는 화면이 없으므로, 조작자 노트북에서 SSH로 미리 접속해 둔다. 핫스팟에 붙도록 와이파이를 미리 등록해 둔다.
- 노트북 A의 IP를 적어 둔다(대시보드 Add a machine 카드의 주소). 핫스팟을 다시 켜면 IP가 바뀔 수 있으니 시연 직전에 다시 확인한다.

## 사전 준비 체크리스트 (시작 30분 전)

- [ ] 모든 기기에 **beta.4**가 설치되어 있다(앱 설정 화면이나 `nodeloom-agent --version`).
- [ ] 모든 기기 충전 완료, 충전기 연결
- [ ] 노트북 A → 프로젝터 미러링 확인, 해상도 1280×720에서 대시보드가 잘리지 않는다
- [ ] 자동 잠금·화면 보호기·절전 끄기(모든 기기)
- [ ] 알림 끄기(방해 금지 모드), 메신저 종료
- [ ] 모든 기기가 같은 핫스팟/공유기에 붙어 있다
- [ ] 윈도우 네트워크가 "개인"이다
- [ ] 리허설에서 쓴 기기 승인 상태를 정한다
  - 윈도우의 최초 승인을 보여줄지, 기존 승인 기기의 재연결을 보여줄지 정한다.
  - 최초 승인 재현이 꼭 필요하면 리허설 때 **Remove → 참여 기기의 Pair as a new machine → 새 코드 승인** 전 과정을 확인한다. Remove는 기존 키를 영구 거부하므로 발표 직전에 임의로 누르지 않는다.
  - 맥은 승인된 상태로 두고 "다시 켜면 자동으로 붙는다"를 보여 줄 수 있다.
- [ ] 라즈베리파이 SSH 창에 `nodeloom-agent --master <마스터-IP>:7878 --enable-fake-runner`를 미리 입력해 두고 Enter만 남긴다. `<마스터-IP>`는 시연 직전 Add a machine 카드의 주소로 맞춘다
- [ ] 와이파이를 끌 **참여 기기**를 정한다. 참여 기기인 Mac 권장, 리허설에서 확정한다. 마스터·공유기·핫스팟의 연결은 끊지 않는다.
- [ ] 실제 장비로 리허설을 두 번 하고 시간과 문제를 기록한다.
- [ ] 성공 장면을 녹화하고 백업 영상이 노트북 A에서 인터넷 없이 재생되는지 확인한다.
- [ ] 화면 녹화와 공유 화면에 관리 토큰·개인 알림이 노출되지 않는다.
- [ ] C의 Demo job과 작업 표시가 있는지 확인한다. 설치 버전의 버튼 이름에 맞춰 대본을 확정한다.

## 진행

### 1. 문제 (30초)

- **발표자**: "집이나 연구실에는 맥, 윈도우 노트북, 라즈베리파이가 다 따로 놀고 있습니다. 이걸 설치 한 번으로 하나의 클러스터로 묶어서, 큰 작업을 나눠서 처리하게 하는 게 Nodeloom입니다."
- 화면: 노트북 A의 바탕화면, Nodeloom 아이콘.

### 2. 클러스터 시작 (1분)

- **조작자(노트북 A)**: Nodeloom 실행 → **Start a cluster here** → **Continue**. 이미 마스터로 설정됐다면 앱을 열어 대시보드를 보여 준다
- 창이 대시보드로 바뀐다. 기기 1대(자기 자신)가 보인다.
- **발표자**: "이 노트북이 클러스터를 운영합니다. 터미널도, 설정 파일도 없습니다. 이 기기도 작업에 같이 참여합니다."

### 3. 기기 추가 (2분)

**윈도우 노트북**

- **조작자(노트북 B)**: Nodeloom 실행 → **Join a cluster** → **Continue**. 화면에 6자리 코드가 크게 뜬다.
- 대시보드에 **Waiting for approval** 카드가 뜬다.
- **발표자**: "같은 네트워크의 클러스터를 스스로 찾았습니다. 아무 기기나 붙으면 안 되니까, 화면의 코드를 대조해서 승인합니다." (노트북 B 화면을 들어 보여 준다)
- **조작자(노트북 A)**: 코드를 확인하고 **Approve**

**맥**

- 승인된 상태라면: 앱을 켜기만 한다. "한 번 승인한 기기는 다시 켜면 알아서 붙습니다."
- 새로 붙인다면: 윈도우와 같다.

**라즈베리파이**

- **발표자**: "화면이 없는 기기는 명령 한 줄입니다. 대시보드의 Add a machine 카드에 그 명령이 나옵니다." (카드를 펼쳐 보여 준다)
- **조작자(SSH)**: 미리 입력해 둔 명령에서 Enter만 누른다. 시연 중에 명령을 새로 입력하거나 주소를 고치지 않는다
- 출력된 코드와 대시보드 코드를 대조해 **Approve**
- 화면: 기기 4대, 각자 CPU·메모리가 실시간으로 보인다.

### 4. 작업 나누기 (1분)

- **조작자(노트북 A)**: **Demo job** 버튼
- 작업 카드에 기기별 구간 막대가 생기고 각자 채워진다.
- **발표자**: "지금은 실제 렌더링이나 음성 전사가 아니라, 분배 동작을 확인하는 테스트 작업입니다. 600개의 테스트 작업 단위가 여러 조각으로 나뉘어 처리되고, 기기마다 맡은 구간과 진행률이 보입니다."
- 첫 작업으로 진행 표시를 설명한다. 테스트 대기 시간은 4대에 균등 분배되면 약 7.5초지만 실제 시간은 리허설에서 확인한다. 실제 렌더링·전사 성능 측정값은 아니다.
- 장애 시연은 5단계에서 **새 작업**을 시작하고 곧바로 연결을 끊는다. 할당 조각이 이미 끝난 기기를 끄면 재배정을 보여줄 수 없다.

### 5. 한 대 빼기 (1분)

- **발표자**: "이제 기기 하나가 갑자기 사라지면 어떻게 될까요?"
- **조작자(마스터)**: 새 **Demo job**을 시작한다.
- **조작자(끌 참여 기기, Mac 권장)**: 자기 기기에 배정된 조각이 진행 중임을 확인하고 곧바로 **와이파이 끄기**. 4대면 작업이 약 7.5초에 끝나므로 시작 직후에 끈다.
- **E**: 연결을 끊은 시각, 다른 기기로 재배정된 시각, 작업 전체가 완료된 시각을 따로 기록한다.
- 기대 결과: 끊긴 기기가 연결 목록에서 빠지고, 미완료 조각이 다른 기기로 넘어가며 이동 표시가 나온다. 끊긴 직후에는 "<기기> left: … wait for another machine…", 넘어가면 "Moved to another machine: … A → B"가 10초 동안 보인다. 남은 기기에서 작업이 **Done**으로 끝나는지 확인한다.
- **발표자(완료를 확인한 뒤)**: "연결이 끊긴 기기의 미완료 조각을 다른 기기에 재배정해 작업을 마쳤습니다. 조각은 처음부터 다시 처리될 수 있습니다."
- **시간 기준**: 전체 핸드오프의 재배정 목표는 10초 이내다. A 문서의 실기기 전체 완료 기준은 15초 이내이므로 A와 기준을 확인하고 각각 측정한다. 리허설 전에는 ‘10초 안에 완료’라고 단정하지 않는다.
- (여유가 있으면) 맥 와이파이를 다시 켜면 자동으로 다시 붙는다.

### 6. 정리 (30초)

- **발표자**: "오늘은 서로 다른 기기의 연결과 승인, 테스트 작업의 분배와 재배정을 보여드렸습니다. 다음 단계는 실제 파일 전송과 Whisper 배치 전사입니다." 실제로 보여준 기기와 성공한 단계에 맞춰 말한다. 영상으로 전환했다면 사전 리허설에서 확인한 동작임을 밝힌다.
- 질문 받기. 받은 질문은 아래 "시연 후 피드백"에 적는다.

## 실패했을 때의 대안

| 상황 | 대안 | 멘트 |
|---|---|---|
| Join 했는데 10초가 지나도 대기 목록에 안 뜬다 | 참여 기기에서 **Enter the address** → 대시보드 Add a machine 카드의 주소 입력 → **Join this address** | "자동 탐색이 지연되어 주소를 직접 넣겠습니다." |
| 윈도우만 안 붙는다 | 네트워크 "개인" 확인 → 방화벽 허용 확인 → 주소 직접 입력. 그래도 안 되면 윈도우 없이 진행 | "윈도우는 지금 연결되지 않아, 연결된 기기들로 계속 보여드리겠습니다." |
| 앱이 이상하다(창이 안 뜸, 멈춤) | 리허설에서 준비한 명령줄 버전으로 전환한다. 같은 기기의 앱은 트레이 **Quit Nodeloom**으로 완전히 종료한 뒤 실행한다. 참여 기기는 `nodeloom-agent --master <마스터-IP>:7878 --enable-fake-runner`, 마스터는 `nodeloom-master`와 브라우저를 사용한다. 현장에서 새로 설치하지 않는다. | "준비해 둔 명령줄 방식으로 전환하겠습니다." |
| Demo job 버튼이 없다 | 설치 버전을 확인한다. 리허설에서 검증했다면 Start a job 카드의 **Custom job**을 펼쳐 Runner를 **Test (sleep only)**로 두고 **Split across machines**. 미검증이면 백업 영상으로 전환 | "같은 테스트 작업을 작업 화면에서 직접 보내겠습니다." |
| 와이파이를 껐는데 넘어가지 않는다 | 끊은 시각과 화면 상태를 기록한다. 20초 동안 재배정 변화가 없으면 준비한 영상으로 전환한다(전환 시간은 리허설 후 확정). 이미 통신이 끊긴 기기의 Quit으로 해결하려 하지 않는다. | "현재 재배정이 지연되어 사전 리허설 영상을 보여드리겠습니다." |
| 라즈베리파이가 안 붙는다 | 주소 직접 입력을 시도하고 계속 실패하면 연결된 기기만으로 진행한다. 미확인 연결을 성공했다고 설명하지 않는다. | "라즈베리파이는 현재 연결되지 않아, 연결된 기기들로 분배 동작을 보여드리겠습니다." |
| 전부 안 된다 | 미리 녹화한 영상을 튼다 | "현장 시연에 문제가 있어, 사전 리허설에서 녹화한 영상을 보여드리겠습니다." |

영상에는 기기 연결·승인, 작업 분배, 참여 기기 와이파이 단절, 재배정과 완료가 담겨야 한다. 녹화 담당은 팀에서 정하고 E는 파일 확보와 재생을 확인한다. 현장 실패 원인이 확인되지 않았다면 네트워크 문제라고 단정하지 않는다.
